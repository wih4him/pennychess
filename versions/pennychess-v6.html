Game rules — quick summary

  • You only move your own (white / "heads") pieces. Black never moves on its own — it only reacts.
  • Goal: get the two pennies (the kings) to land on the same square.
  • No piece is ever captured or removed. Pieces only move, swap places, or "stack."
  • A Rook/Bishop/Queen's force always stops at the very first piece in its line — that piece alone is affected, and nothing beyond it is reached this step.
  • After every move, the board settles in a series of "steps." Every single movement in a step — even an unambiguous one — is shown to you with an arrow before it happens, and a step only applies once you've resolved every choice in it and clicked Apply Step.
  • If two or more forces would act on the same piece (or two pieces would land on the same square) within one step, you pick which one wins before that step can apply.
  • A pawn can move onto its own penny to "shield" it — a shielded penny ignores every force except from an opposing Queen.
  • See "Full Rule Set" in the left sidebar for the complete, detailed ruleset.
Design notes & what's not implemented yet

Built from Pennychess 1.1, "BOTH Rules and Puzzles" (the fullest, most-current rules+puzzles document in the folder — it already folds in the level progression and the Multidimensionality/Non-Euclidean clause) plus the standalone "MORE levels" PDF (Queens Corner, Knights Only, Four-Nineties). The other PDFs in the folder are earlier or parallel drafts of the same material and weren't used as the source of truth.

Interpretation calls made (the source is a personal notes document, not a spec — these are reasonable readings, not certainties):

  • Kings/Pennies move normally like a chess king (1 square, any direction) — "purely reactionary" is read as "has no push/pull effect on others," not "cannot be moved."
  • Queen effect = Rook's pull along its straight lines, Bishop's push along its diagonals.
  • Rook/Bishop/Queen effects apply to opposite-color pieces only. The doc's literal text ("attracts same," "pushes same") reads as affecting your own pieces too, but that was tested and rejected: it makes the initial pre-move board-check on the standard Level 1 setup cascade into an outright win at 0 moves (your own queen/bishop are diagonally touching your own pawn at the start of any standard game), which contradicts the doc's own "6 MOVE-MINIMUM SOLVE" for that level. Pawn's same-color rule ("neutral") is unambiguous in the source, so that one rule was extended to Rook/Bishop/Queen for a playable result.
  • Every ray "short-stops" at the first piece it meets — always, no exceptions. The source doc's exact text ("a pawn blocks ALL effects... EXCEPT opposing-pawns and opposing-queens") reads as those two sources reaching a SECOND piece standing behind a pawn. v4 implemented exactly that, literally. In practice a single ray producing two separate targets/arrows in one step made the reaction system hard to read at a glance — "which object is this force actually about" stopped being obvious. v6 simplifies to: the first piece a ray reaches is always the only target, full stop, for every source including pawns and queens — a deliberate simplification traded for legibility over that one clause's literal fidelity.
  • Levels 2/3's parenthetical ("only friendly/opposing pawns and kings") is treated as loose flavor text; the literal sentence ("standard, minus opposing/friendly pawns") is what's built.

Not implemented in this prototype — flagged rather than faked:

  • Multi-board / non-Euclidean boards (the "Standard, Both Boards" level is shown locked).
  • Knight-portal chains through a second knight elsewhere on the board (a single knight is transparent to a passing force as of v4 — see below — but the fuller multi-knight portal-network version isn't built).
  • Castling.
  • Quantum-tunneling as an optional player choice rather than automatic (the source doc frames it as optional; this build auto-resolves it — see v4 changes below).

v2 changes from v1: non-blocking arrow-based conflict UI, board coordinates, piece cheat-sheet, level descriptions, simplified rules summary.

v3 changes from v2: fixed the arrow overlay corrupting the board's CSS Grid layout (it used explicit grid placement over cells the auto-placed squares also needed — moved to absolute positioning instead, which doesn't touch grid flow).

v4 changes from v3:

  • Pawns can now move 2 squares on their first move (both squares must be empty), tracked per-pawn.
  • Knight force-effects rebuilt: Knortal (transparent to ray-based push/pull), Kuantum-tunneling (a push/pull landing on a knight swaps instead of blocking), and Kneleportation (the knight's own move onto an occupied square swaps places). Replaced the old "auto-swaps with an opposing knight in range" mechanic, which wasn't in the source ruleset and was the real cause of pieces getting shoved around near knights.
  • Dead-End detection: the same conflict recurring 3 times in a row auto-resolves as no movement ("Net Force Zero...") instead of being re-prompted a 4th time.
  • New history panel (Last Reaction / Last Action-Move while active, full scrollable History when idle) and the Full Rule Set / FAQs dropdowns.

v5 changes from v4:

  • The Solved screen now distinguishes outcomes: "Perfect Solve!" on hitting the listed move-minimum exactly, "NEW RECORD!" on beating it, "Solved!" otherwise.
  • The reaction system was rebuilt around full step-by-step transparency: every movement in a step, including unambiguous ones, is shown with its own arrow before the step applies, and the step only commits once every real choice has been made and Apply Step is clicked.
  • Arrow colors are generated per-render for whatever's on screen, instead of indexed into a fixed palette — fixed a latent mis-colored-arrowhead bug.

v6 changes from v5:

  • Rays short-stop at the first piece, always. See the interpretation-call note above — this replaces v4/v5's "a pawn doesn't block an opposing pawn/queen, so the ray can reach a second piece behind it" behavior. A single force now only ever has one possible target, which is what "arrows" was always meant to communicate clearly. This doesn't undo the v4 queen-pull bug fix — a ray still always registers the first piece it reaches as a real target; it just never looks past that piece anymore.
  • Last Reaction, Last Action/Move, and the Actions+Reactions History are now all shown together, always — during idle turns between moves and mid-reaction alike. Previously the panel swapped between "Last Reaction + Last Action" (mid-reaction) and "History" (idle); now all three stack permanently below the Reactions panel.
  • Reactions vs. Decisions, communicated explicitly. A "Reaction" is any resolved force, whether or not it had more than one possible outcome; a "Decision" is specifically a Reaction where you had to pick between competing outcomes. The Reactions panel title now reads REACTION: Single for a step that's (so far) the only one triggered by your move, or CHAIN-REACTION: Step N once a second step follows — note this is a step-counter ("Step N"), not a look-ahead "steps remaining" count, since how many more steps a chain will need isn't knowable in advance (it can depend on choices not yet made). When 2+ movements are happening in the same step, an italic subtitle reads "Simultaneous Reaction(s)"; if any of those are genuine Decisions, it reads "Simultaneous Reaction(s) + Decision(s)" instead. The apply-gate status line now reads "Exercise FREE WILL to steer the fate of this step." in place of the old "Review and apply this step."
