Game rules — quick summary

  • You only move your own (white / "heads") pieces. Black never moves on its own — it only reacts.
  • Goal: get the two pennies (the kings) to land on the same square.
  • No piece is ever captured or removed. Pieces only move, swap places, or "stack."
  • After every move, the board automatically settles: pieces push, pull, or swap based on what's in range, in a chain, until nothing more happens.
  • If two or more forces try to act on the same piece (or two pieces are pulled to the same square), the "Reactions" panel on the right shows the arrows and lets you pick which one wins.
  • A pawn can move onto its own penny to "shield" it — a shielded penny ignores every force except from an opposing Queen.
Design notes & what's not implemented yet

Built from Pennychess 1.1, "BOTH Rules and Puzzles" (the fullest, most-current rules+puzzles document in the folder — it already folds in the level progression and the Multidimensionality/Non-Euclidean clause) plus the standalone "MORE levels" PDF (Queens Corner, Knights Only, Four-Nineties). The other PDFs in the folder are earlier or parallel drafts of the same material and weren't used as the source of truth.

Interpretation calls made (the source is a personal notes document, not a spec — these are reasonable readings, not certainties):

  • Kings/Pennies move normally like a chess king (1 square, any direction) — "purely reactionary" is read as "has no push/pull effect on others," not "cannot be moved."
  • The automatic in-range Knight swap is read as applying only between two opposing knights ("counterpart"), matching the counterpart-specific pattern every other piece entry uses. A knight's own player-driven move can still swap with any piece of any type.
  • Queen effect = Rook's pull along its straight lines, Bishop's push along its diagonals.
  • Rook/Bishop/Queen effects apply to opposite-color pieces only. The doc's literal text ("attracts same," "pushes same") reads as affecting your own pieces too, but that was tested and rejected: it makes the initial pre-move board-check on the standard Level 1 setup cascade into an outright win at 0 moves (your own queen/bishop are diagonally touching your own pawn at the start of any standard game), which contradicts the doc's own "6 MOVE-MINIMUM SOLVE" for that level. Pawn's same-color rule ("neutral") is unambiguous in the source, so that one rule was extended to Rook/Bishop/Queen for a playable result.
  • Pawn-blocking exception (effects from opposing pawns/queens pass through a blocking pawn) is implemented; effects from everything else stop at the first piece in the line.
  • Levels 2/3's parenthetical ("only friendly/opposing pawns and kings") is treated as loose flavor text; the literal sentence ("standard, minus opposing/friendly pawns") is what's built.

Not implemented in this prototype — flagged rather than faked:

  • Multi-board / non-Euclidean boards (the "Standard, Both Boards" level is shown locked).
  • Knight "portal" pass-through for other pieces' effects, and the optional adjacent quantum-tunneling swap between turns.
  • Castling.
  • Pawn's optional two-square first move (kept to 1 square everywhere for simplicity).

v2 changes from v1:

  • The old full-screen "multiple forces" dialog is gone. Conflicts now show as arrows on the board plus a non-blocking panel on the right, so the board is never hidden.
  • Rank/file coordinates (a–h, 1–8) added around the board.
  • Added the piece cheat-sheet, level description, and simplified rules panels below the board.

v3 changes from v2 (bug fixes only — no rules-engine changes, same move-generation, same board-check/cascade logic, same 40-step cap):

  • Fixed: the arrow overlay used CSS Grid explicit placement to span the board area, which made the browser's auto-placement algorithm treat those 64 cells as pre-occupied and shove the real board squares out of position — this was the "black box that distorts the board" bug. Fixed by taking the arrow layer out of grid flow entirely (absolute positioning instead), which doesn't disturb the grid's own auto-placed squares.
  • Bishop/Queen force logic itself was never broken — isolated testing confirmed both push/pull correctly. The "bishops and queens don't seem to work" report was this same rendering bug, surfacing most often on diagonal conflicts.
